# 演播厅预约管理系统

学校演播厅预约管理系统，支持多角色审批流程，覆盖从申请提交到事后报告的全流程管理。

---

## 功能特点

### 📅 预约申请
- 在线提交演播厅使用申请（每次不超过 3 小时）
- 选择会议主题、类型、使用时间、现场联系人
- 系统自动校验时间冲突

### ✅ 多级审批流程

| 步骤 | 角色 | 操作 |
|------|------|------|
| 1 | 申请人 | 提交使用申请 |
| 2 | 部门主管 | 部门级别审批 |
| 3 | 演播厅主管 | 终审并分配执行管理员 |
| 4 | 执行管理员 | 使用后提交检查报告 |

### 🎨 色块时间可视化
- 按时间段颜色区分预约：上午橙、午间粉、下午蓝、傍晚紫、晚间紫罗兰
- 首页工作台色块条：直观展示每日各时段预约分布
- 迷你色块条：每条记录下方显示时间刻度
- 色块视图 / 时间线视图 一键切换

### 📊 公示栏
- 已完成使用记录的评分公示（合格/不合格印章）
- 得分详情 + 检查项（物品归位、卫生保持、公物损坏）
- 支持照片查看

### 📋 事后报告
- 执行管理员提交使用后检查报告
- 评分（0-10 分，支持小数）
- 上传现场照片（按分类）

### ⏰ 催办提醒
- 自动追踪各审批环节耗时
- 一键发送催办提醒给当前审批人

### 👥 角色管理
- 五种角色：申请人、部门主管、演播厅主管、执行管理员、系统管理员
- 基于角色的权限控制
- 学部管理、用户管理

## 技术栈

| 层 | 技术 |
|---|------|
| 后端框架 | Python FastAPI |
| 数据库 | SQLite（aiosqlite 异步驱动） |
| 认证 | JWT（pyjwt）+ bcrypt 密码哈希 |
| 前端 | Jinja2 模板 + 原生 JavaScript + Tailwind CSS |
| 部署 | Docker + docker compose |

## 快速开始

### 使用 Docker

```bash
git clone https://github.com/wobuzhidao3001-art/studio-booking.git
cd studio-booking
docker compose up -d
open http://localhost:8000
```

### 手动部署

```bash
pip install -r requirements.txt
python3 -c "import database; database.init_db(); database.seed_db()"
python3 main.py
```

## 解决的核心痛点

| 痛点 | 解决方案 |
|------|---------|
| 演播厅使用冲突 | 系统自动校验时间冲突，同一时段不可重复预约 |
| 审批流程不透明 | 多级审批 + 状态追踪，申请人随时查看进度 |
| 使用后无人检查 | 强制提交事后报告，评分 + 照片留痕 |
| 公示不直观 | 色块时间条可视化 + 合格/不合格印章 |
| 催办不及时 | 一键催办提醒，自动追踪各环节耗时 |
| 管理分散 | 统一后台管理：用户、学部、会议类型、历史数据 |
